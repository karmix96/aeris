COMMON FOLDER — FOUNDATION LAYER
================================

Purpose
-------
Infrastructure backbone of AERIS.

This layer handles:
- config loading
- path resolution
- data/output directory conventions
- run folder creation
- logging setup

It must stay domain-neutral.

It must NOT contain:
- BWB geometry logic
- AVL / CFD solver logic
- ML training logic
- QC policy logic
- dynamics / trim logic


Key modules
-----------

config.py
    load_yaml_config()
    file_sha256()

    Loads YAML safely with minimal structural validation.
    Computes config/file hashes for future reproducibility manifests.
    Does not perform domain-specific schema validation.

logging_utils.py
    setup_logger()
    make_process_log_file()
    log_and_echo()

    Creates rotating file logger plus optional console logger.
    Closes old handlers correctly.
    Avoids default logger-name collisions by deriving names from log paths.
    Supports text logs and JSON-lines logs.

paths.py
    PROJECT_ROOT
    CONFIGS_DIR
    DATA_DIR
    RUNS_DIR
    DATASETS_DIR
    create_run_folder()
    describe_path_environment()

    Resolves project/config/data directories.
    Supports editable installs, packaged installs, Windows/Linux machines,
    cluster scratch, and cloud-style output directories.


Environment variables
---------------------

AERIS_PROJECT_ROOT
    Optional project/source/workspace root.

AERIS_CONFIGS_DIR or AERIS_CONFIG_ROOT
    Optional explicit configs directory.

AERIS_DATA_DIR or AERIS_DATA_ROOT
    Optional explicit generated-data/output directory.

AERIS_USE_CLUSTER_SCRATCH
    If true and no explicit data dir is set, prefer SLURM_TMPDIR, SCRATCH,
    or TMPDIR for generated output.


Recommended cluster example
---------------------------

export AERIS_PROJECT_ROOT="$PWD"
export AERIS_CONFIGS_DIR="$PWD/configs"
export AERIS_DATA_DIR="$SCRATCH/aeris_data"


Production principles
---------------------

1. Source code location is not output location.
2. Generated data should be redirectable.
3. Every run gets its own folder.
4. Run folders are timestamped and collision-resistant.
5. Logging should be persistent, rotating, and optionally quiet.
6. Parallel workers should not write to the same log file.
7. Common utilities should be boring, stable, and domain-neutral.
